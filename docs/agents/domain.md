# Domain Docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read ADRs under `docs/adr/` that touch the area being changed.
- If those files do not exist, proceed with the available project context. The `/domain-modeling` skill creates them when terminology or decisions are resolved.

## Vocabulary

Use the glossary's vocabulary in issue titles, refactor proposals, hypotheses, and test names. If a needed concept is not defined yet, record the gap for `/domain-modeling` instead of silently inventing a competing term.

## Conflicts

If a proposed change contradicts an existing ADR, surface the conflict explicitly and ask whether the decision should be reopened.
