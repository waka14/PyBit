# PYBIT 重启重构视觉原型规范

## 这次原型要解决的问题

PYBIT 是一个给受邀成员使用的私募小程序账本。它不是公开交易平台，也不是营销网站，首要任务是让成员在几秒内确认自己的当前投资余额、累计盈亏、最近几场的资产变化，以及某一场的完整结算明细。管理员还需要在同一个信息体系里创建场次、录入毛结束金额、查看手续费和抽水、审核转回申请、管理成员。原型只讨论视觉和信息组织，不改变现有 Supabase、权限、认证、数据模型或计算规则。

## 使用者与任务

普通成员主要看收益、查看资产、调整下一场参与比例、提交转回申请；备用管理员 waka 还可以管理场次和成员；主要管理员 czh 需要额外处理审核、待转回资金和成员管理。三种身份共享同一套导航和数据语言，差别只体现在可见操作和管理区，不通过颜色单独表达权限。每个页面必须让人知道自己看的是生产账本还是演示数据，金额统一使用 B 单位并保留两位小数，百分比最多两位小数。

## 需要保留的真实内容

首页保留“当前总资产、累计盈亏、累计收益率、资产走势、近 5 场/近 10 场/全部、资产折线/场次 K 线、点选场次后查看八项明细、上一场/下一场”。资产页保留“当前投资余额、可用余额、账上待转回余额、实际转回余额、调整下场参与比例、CZH 剩余比例、取回资金、申请记录”。账本页保留“待审核转回、成员管理、成员可退出资金、新增场次、场次列表、毛结束金额录入、核对并结算、删除与恢复、撤销提示”。空状态、错误、保存中、离线、表单错误、禁用按钮和焦点状态也属于设计内容。

## 输出尺寸与限制

每个原型同时覆盖 1440×900 桌面宽度和 390×844 手机宽度，使用纯 HTML/CSS/少量内联脚本，不依赖图片、外部字体或第三方资源。因为这是数据型操作界面，本轮不放内容图片；如果需要氛围，只用 CSS 图形、网格、噪点、像素边框和数据标记。页面上的数据均标记为“合成演示数据”，不让人误以为是线上真实账本。三版使用完全相同的文案和数字，只改变视觉方向与信息骨架，便于比较。

## 三种方向

### 方向一：裂屏终端 / 深度队列

黑色发光底，灰白尘点和琥珀色信号作为唯一强调。信息像一张 2 点钟的复古终端工作队列，层级通过前后深度、亮度和字距表达，不把所有内容装进卡片。首页优先展示大金额和走势，明细沿基线展开；适合强调“账本正在运行”和快速扫读。风险是数据密度过高时可能不够亲切，所以必须保留清晰的中文标题、较大的点击区域和可读的手机顺序。

### 方向二：报告工作台 / 趋势优先

以温暖的灰白纸面、深靛蓝文字和一枚珊瑚信号色建立“月度报告”感觉。首页是报告摘要，下面是连续走势和可展开的场次表；资产页强调余额构成，账本页强调操作状态和审核队列。它借鉴成熟个人财务产品常见的“摘要、趋势、明细”阅读顺序，但不复制任何品牌界面。适合希望降低学习成本、先看结论再查证据的成员。风险是容易变成普通后台，因此需要用明显的 PYBIT 标识、独特的数字排版和少量像素化状态符号保留个性。

### 方向三：纸牌账本 / 牌桌冒险

以深色桌面、象牙纸牌、金色筹码和青绿色状态光构成原创的“纸牌账本”。纸牌不是游戏装饰，而是把当前总资产、盈亏、场次快照做成容易记忆的物件；真正的管理表格仍然采用直线列表，避免把每一行都做成卡片。首页像摊开的牌局记录，资产页像手里的资金牌，账本页像一张带操作栏的庄家记分纸。它最贴近项目原本的像素纸牌气质，辨识度强，也能让场次概念更自然。风险是装饰过多会削弱财务可信度，所以金额、公式说明和权限提示必须保持克制、对齐和高对比度。

## 共同质量线

三版都必须保留直接中文、明确的正负颜色含义、键盘焦点、可读对比度、响应式布局，以及“不用动画阻塞操作”的原则。生产页面实施时先改共享视觉基础，再按“收益、资产、账本”逐页迁移，最后补生产环境的 PWA 更新提示。任何涉及 Supabase 表结构、RLS、RPC、登录流程或金额计算的改动都不属于本轮视觉重构，必须单独提出并测试。
