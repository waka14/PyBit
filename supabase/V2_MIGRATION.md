# PYBIT V2 迁移准备

本轮只准备迁移，不应用到生产。

## 隔离验证顺序

1. 新建一次性 Supabase 项目，依次执行四份 migration；本轮只准备文件，不执行生产迁移。
2. 建立 CZH、waka 和两位普通股东的受邀身份绑定。
3. 用 `app_v2_configure_openings` 写入逐人的期初资产和比例；正式值必须来自生产对账，演示值可用三位股东各 B1,000／30%，CZH B1,000／10%。
4. 分角色运行 `tests/v2-rls-smoke.sql` 与 `tests/v2-change-plan-smoke.sql`，确认普通股东不能读表、管理常规比赛或篡改他人委托。
5. 导入脱敏比赛副本，逐人核对当前资产、累计比赛盈亏、累计投入、收益率、CZH 抽水与大盘总额。
6. 验证失败时停用 V2 前端并保留 V1 表；V2 migration 没有删除 V1 表。

## 生产切换前需要确认

旧记录含3%手续费、旧版进行中场次和取回流程，不能自动套用新口径。新委托使用待接手→执行中→已结算并锁定可用资产；常规比赛不抽水，单独委托盈利抽10%。准备一份逐人对账预览后，用户需要选择：保留旧历史并以核对余额作为 V2 期初，或追溯重算选定比赛。推荐前者。

## 回退

前端回退到上一部署版本；数据库停止调用本轮新增 `app_v2_*` RPC。V1 表未被删除，V2 表留作审计。任何生产清理都另行制定 SQL，不在本迁移中自动执行。

## 本轮执行边界

本轮已准备 `202609120001_pybit_v2_change_plan.sql`、适配器命令和静态 smoke 文件，但没有运行 Supabase CLI、SQL Editor、历史重算、生产数据库迁移或正式发布。迁移前仍需在隔离库验证锁定金额、并发 revision、RLS 和逐人余额对账。
