# PYBIT V2 开发启动 prompt

请继续维护和完善已经落地的 PYBIT V2 手机网页版。先完整阅读项目 AGENTS.md 和 `.scratch/pybit-v2/spec.md`，以该指导文件作为功能规则的依据。与旧历史交接文件或原型冲突时，以本轮新需求为准，并同步更新受影响的文档。

我不是程序员，技术选型和常规实现细节由你推荐执行。用简明中文汇报结论、风险和需要我决定的业务问题。先固定页面结构和基础操作，再实现账务与权限及可用手机页面，最后进入视觉设计。此前三种视觉原型未被选定。

请按 Matt Pocock skills 的方法推进：阅读实际安装且适用的技能，调查现有代码，明确业务术语，将需求拆成可验证的本地 Markdown 任务，按依赖逐项实现、测试和审查。不要假定所有技能已经加载或可调用；缺少辅助技能时，采用等效流程继续已授权工作。

先核查 `src/v2/` 账务模型、Supabase V2 迁移与服务端权限、生产和演示两套适配器的差异。将新增任务保存在 `.scratch/pybit-v2/issues/`，一项一文件，并维护依赖和状态。修改账务时先补测试，再修改实现。任务完成以 spec.md 的验收清单和实际检查结果为依据。

指导文件中的“建议默认”可以作为实现默认值，汇报采用情况即可；发现业务冲突或存量数据无法可靠迁移时，提出具体问题，并继续不依赖该问题的本地工作。生产历史是否追溯新抽水、期初余额切换方式和线上迁移发布，需要在准备好数据对比及回退方案后由我确认。

金额、抽水、直接资金增减、单独委托、历史修改删除、角色权限和图表口径，均按 spec.md 执行。保留登录、退出、按权限导出和手机网页入口，并使生产与演示计算一致。保护 `sources/` 下只读资料及已有无关修改，真实账本不用于试验数据。

交付时说明完成了什么、如何本地预览、各角色如何验收、检查结果、尚存限制和待发布步骤。当前授权覆盖本地实现、隔离环境验证和部署材料准备，不包含未经确认的生产数据迁移或发布。
